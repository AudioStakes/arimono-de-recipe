# 材料フォームと文字拡大の改善 — 2026-10-18

## 問題と設計

材料追加後の量欄は96〜152pxの固定幅で、長いplaceholderを表示しきれなかった。量だけに上部ラベルがあり、名前の編集面と高さ・上端も揃っていなかった。

会話履歴を引き継がない設計担当が、既存HTML/CSSを読む前に利用者の操作から案を作成した。採用した順序は、ラベル付きの材料名と量、全幅の量の例、材料の使い方、右寄せの削除。以前の重なったGridを取り除き、名前と量は同じ46px以上の操作面とした。幅や文字サイズに応じて縦に並び、文字を縮めない。

名前は既存の「値を押して編集する」動作を保つ。長い名前の入口は1行の省略表示と全文のaccessible name・titleを持ち、編集時はnative inputで全文を扱う。IME、Enter、Escape、blur、材料ID・量の保持は既存の入力処理を使う。量の例は入力中も読め、`aria-describedby`で関連付ける。使い切る場合の量必須という意味と、依頼文の出力規則は変更しない。

## 全体監査と修正

別の読み取り専用担当が、材料以外の全入力・モデル・操作・回答・プレビュー・プライバシーを調べた。再現できた次の問題も修正した。

| 問題 | 改善 |
| --- | --- |
| 他の入力欄の例も狭幅や文字拡大で欠ける | 候補入力と補足の例を、常設で折り返す補助文へ移した。入力に関連付け、役割の例は目的に合わせて更新する |
| 320pxの本文コピーが途中で改行し、文字200%では固定の送信ボタンが約38pxまで縮む | 本文と固定欄に同じ必要幅による折返しを適用。通常文言は1行、収まらなければ操作を縦に並べる。長いコピー失敗表示は折り返す |
| モデルselectの固定46px高さで拡大文字が欠ける | Safariの明示高さを維持しながら、フォントに合わせて46px以上へ伸ばす |
| 360px・文字200%で人数「10人」が2行になる | カードの最小幅から列数を決め、人数を1行にする |
| 作りたい料理・単一の料理役割を確定すると入力が消え、focusがBODYへ落ちる | 入力中・候補選択の確定では指定値の編集ボタンへfocusを渡す。外部操作からの確定でfocusを奪わない |

320/360/390/1280pxと文字16/20/32pxの12条件をChromiumで独立確認した。修正後は全条件で横はみ出しなし、操作文言と人数は1行、モデルの縦欠けなし。最終フッターのプライバシーは固定操作に隠れず、文字が大きい場合の余白も確保できた。入力・候補それぞれのEnterで、料理と単一役割の4経路のfocusを確認した。コピー失敗時の長文にも横はみ出しはなかった。
