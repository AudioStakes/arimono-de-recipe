# ありもの de レシピ

家にある食材から「今日、何を作るか」を考える日本語のWebアプリです。材料・人数・調理時間・使えない食材などを入力すると、短い料理候補を表示したり、普段使っているAIへ貼り付けるレシピ依頼文を作ったりできます。

## できること

- 材料ごとに「おまかせ」「必ず使う」「使い切る」と分量を指定する。
- **今日の候補を見る**: Cloudflare Workers AIで3つの料理候補を作り、候補の詳細と「材料」「作り方」「味の調整」のタブを確認する。
- **AI向けレシピ依頼文をコピー**: 入力した条件を含む依頼文をコピーし、ChatGPT、Claude、Geminiなどに自分で貼り付ける。Cloudflareの設定やAPIキーは不要です。
- スマートフォンとキーボードでも操作する。アカウント登録はありません。

例えば「豆腐、キャベツ」を追加し、豆腐を「使い切る・150g」にすると、その条件を料理候補や依頼文に反映できます。AI候補の生成に失敗しても依頼文コピーは使えます。

現在、公開デモURLはこのREADMEに掲載していません。自分で動かす方法は以下を参照してください。

## 最初に動かす

Node.js **22.12以上の22系**または**24以上**とnpmが必要です。CIはNode.js 22を使用します。[`.nvmrc`](.nvmrc)も22系を指定しています。

```bash
git clone https://github.com/AudioStakes/arimono-de-recipe.git
cd arimono-de-recipe
# nvmを使う場合: nvm install && nvm use
npm ci
npm run dev
```

ターミナルに表示されるURL（通常は `http://127.0.0.1:5173`）を開き、材料を追加して依頼文コピーを試せます。コピーをブラウザが許可しない場合は、表示中の依頼文を選択して手動でコピーしてください。

`npm run dev` はViteだけを起動します。**このモードでは `/api/recipe` が動かないため、AI候補は生成できません。** アプリ内AIも使う場合は[Cloudflareでの公開・ローカル確認](docs/deployment.md)を参照してください。

```bash
npm run build
npm run preview
```

ビルド成果物は `dist/` に出力します。静的ホスティングだけでも依頼文コピーは利用できます。アプリ内AIにはルートの `functions/` とCloudflareの `AI` バインディングが必要です。

## 入力とAI候補の制約

買い足しなしが基本です。入力した材料のほか、塩・油・しょうゆ・だし等の基本調味料を家にあると仮定します。持っていないものは「NG食材・調味料」に指定してください。現在の画面には買い足しを許可する操作はありません。

AI候補は短い参考情報です。材料は最大6項目、手順は最大3項目で、調味料の具体的な分量や加熱条件が十分に揃わない場合があります。NG指定の検証は文字列の照合であり、別名・派生原料・交差接触の判定には対応していません。アレルギー対応や調理の安全性を保証するものではありません。実際に作る前に材料と手順を確認してください。

| AI候補へ送る項目 | 上限 |
|---|---:|
| 家にある食材・材料 | 12件 |
| うち「必ず使う・使い切る」と指定する材料の合計 | 6件 |
| 料理の要望（方向性・役割・作りたい料理・合わせる料理の合計） | 5件 |
| 調理方法・調理器具 | 8件 |
| NG食材・調味料 | 8件 |
| 各材料名・各要望・分量 | 80文字 |
| 補足 | 180文字 |

人数は80文字、時間は40文字までです。全体にも送信サイズの上限があります。上限を超えた入力は一部を黙って省くことなく、画面で修正を案内します。**依頼文コピーにはAI候補用の件数制限を適用しません。** 30秒で応答を受け取れない場合も、コピーを続けて利用できます。

## 入力内容の扱い

- 入力・依頼文生成・コピーはブラウザ内で行います。
- **「今日の候補を見る」を押した時**に、材料と指定した条件を同じサイトの `/api/recipe` に送り、Cloudflare Workers AIで処理します。コピー操作だけでは外部AIへ自動送信しません。
- アプリのコードには入力の永続保存・ログ出力・アクセス解析・ログイン機能はありません。再読み込みすると入力は失われます。
- ホスティング事業者や、自分で貼り付けるAIサービスによるデータの取扱いは各サービスの方針に従います。自由記述には氏名などの個人情報を入れないでください。

公開運用時の呼び出し制限・費用・バインディング設定については[公開手順](docs/deployment.md)を確認してください。
